# 智能大学课表 Web MVP 产品设计文档

版本：v0.1  
日期：2026-09-16  
状态：初版设计，可用于原型设计和开发拆解

## 1. 产品定位

面向大学生的个人网页课表工具。用户通过上传课表截图快速建立课表，再通过本周课表和今日课程确认什么时候上课、上什么课、在哪里上课。

首版的核心价值是降低录入成本，并准确表达大学课程的教学周、节次和临时变更。“智能”主要体现在截图识别和核对辅助。

### 1.1 首版设计假设

- 手机浏览器是主要使用入口，兼容电脑浏览器。
- 先面向一所学校的小范围试用，优先验证该校常见课表截图。
- 无需注册登录，保存一份当前学期课表；不提供跨设备同步。
- 课表保存在当前浏览器，截图识别需要联网。
- 支持导出备份和恢复，减少本地数据丢失带来的影响。
- 不接入教务系统，不获取学生的教务账号或密码。

以上是首版的范围选择；目标学校、视觉风格和识别服务供应商尚未确定，不影响先开展页面原型设计。

## 2. 目标用户与核心场景

目标用户是已有教务系统课表截图、希望在手机上快速查课的大学生。

| 场景 | 用户需求 | 产品响应 |
|---|---|---|
| 学期开始 | 不想逐节手动输入课表 | 上传截图，识别后核对保存 |
| 出门前或课间 | 想知道下一节课及教室 | 首页展示当前或下一节课程 |
| 安排本周事务 | 想查看某天是否有课 | 查看本周课表并切换日期、教学周 |
| 单双周课程 | 不确定本周某门课是否上课 | 根据实际教学周显示有效课程 |
| 临时通知 | 某次课停课、换教室或调整时间 | 仅修改指定日期的课程安排 |
| 换浏览器或设备 | 希望保留已经录好的课表 | 导出备份，再在新浏览器恢复 |

## 3. MVP 目标与验证方式

产品闭环：设置学期 → 上传截图 → 核对课表 → 保存 → 日常查看 → 修改安排。

首轮邀请 10–20 位学生试用，以下为待验证目标，并非已有结果：

| 指标 | 初始目标 | 测量方式 |
|---|---|---|
| 首次建表耗时 | 中位数不超过 3 分钟 | 从开始学期设置到首次保存，含用户核对时间 |
| 独立完成率 | 至少 80% 的试用者不需要现场指导 | 观察是否完成设置、导入和保存 |
| 识别质量 | 支持范围内的截图，关键字段准确率达到 90% | 对照人工标注，分别统计课程名、星期、节次、周次、教室；漏课计入错误 |
| 日常使用 | 至少 50% 的试用者在随后 5 个教学日中使用 3 天及以上 | 经同意的匿名使用记录或试用访谈 |
| 排课正确性 | 周次计算、课程筛选和单次调课的验收案例全部通过 | 使用固定日期和课表样例验收 |

试用反馈需要区分识别错误、核对困难和课表显示错误，分别改进。识别速度和失败率先记录实际表现，再制定正式服务指标。

## 4. 功能范围

### 4.1 P0：首发必需

| 模块 | 首版功能 |
|---|---|
| 学期设置 | 学期名称、第一教学周的周一、总周数、每天的节次和时间 |
| 截图导入 | 单张截图上传、识别状态、失败重试、识别结果预览 |
| 核对编辑 | 字段修改、缺失项提示、疑似冲突提示、批量确认保存 |
| 课程管理 | 手动添加、编辑课程及上课安排、删除课程 |
| 课表查看 | 今日课程、本周课表、切换周次、返回本周、课程详情 |
| 周次规则 | 连续周、单双周、自定义周次、多组上课安排 |
| 单次变更 | 指定日期停课、修改教室、改期，以及添加一次性补课 |
| 数据管理 | 浏览器本地持久保存、备份导出、备份恢复 |

### 4.2 后续候选

- P1：安装到桌面、离线查看、课表图片导出、日历文件导出。
- P1：在验证需求后加入账号和多设备同步。
- P2：网页推送、更多学校课表格式、多图或文件导入。
- 暂不规划进首版：教务系统自动登录、成绩查询、选课推荐、作业管理、AI 学习计划、社交功能、聊天问课表。

网页关闭后不能依赖页面定时器可靠提醒。首版不提供课前通知，也不展示暗示具备通知能力的入口。

## 5. 信息架构与页面设计

主入口为“课表”；“添加课程”“导入课表”“设置与备份”作为辅助入口。首次无数据时，优先引导创建课表。

### 5.1 首次进入与学期设置

空状态文案：“导入课表，随时查看下一节课。”主按钮为“创建我的课表”。

设置字段：

| 字段 | 要求与规则 |
|---|---|
| 学期名称 | 必填，可自动建议名称，允许修改 |
| 第一教学周的周一 | 必填，使用日期选择器，明确说明不是任意开学日期 |
| 学期总周数 | 必填，默认 20，允许设置为 1–30 周 |
| 每日节次 | 提供可编辑模板，支持 1–16 节；模板注明需要按学校作息核对 |
| 每节课时间 | 必填，开始早于结束；节次按时间递增且不得重叠 |

填写完成后，可选择“上传截图”或“手动添加课程”。用户跳过截图导入也能使用完整课表功能。

### 5.2 截图导入页

- 支持 JPG、PNG、WebP，单次上传一张，大小不超过 10 MB。
- 提供文件选择；手机端使用系统图片选择器，电脑端支持拖入。
- 提示上传清晰、完整、可辨认星期和节次的周课表截图，避免包含姓名、学号等无关信息。
- 上传前展示图片预览，允许移除并重新选择。
- 点击“开始识别”后显示明确的处理中状态，避免重复提交。
- 识别期间离开页面时提示任务将中断；首版不提供后台任务或跨页面恢复。
- 超过 5 分钟未完成时结束等待，提供“重试”和“手动添加”入口。
- 图片无效、无课程或格式无法解析时说明原因，保留重新上传入口。

首版优先支持星期为列、节次为行、课程内容以文本呈现的课表截图。PDF、Excel、手写课表和任意复杂版式不在首版承诺范围内。

### 5.3 识别核对页

电脑端并排展示原图与识别列表；手机端提供可展开的原图预览，下方逐条显示上课安排。

每条安排包含课程名称、教师、教室、星期、起止节次和周次。用户可编辑、删除误识别条目、补充遗漏课程，并预览整周排布。

规则：

- 课程名称、星期、起止节次、周次必填，缺失或无效时必须修改才能保存。
- 教师和教室可空；缺失教室显示“教室待补充”，允许保存。
- 图片未写周次时标记“周次待确认”，提供“设为全学期”的快捷操作，不自动当作全学期。
- 疑似重复、时间冲突以及识别服务明确标记的不确定项突出提示；不向用户展示没有校准依据的置信度百分比。
- 每条必填错误就地展示，保存入口汇总剩余问题数。
- 冲突和疑似重复允许用户确认后保留；缺失必填字段不能跳过。
- 保存前明确提醒核对星期、节次、周次和教室。
- 识别结果作为草稿，只有用户确认后才写入正式课表。

已有课表时，再次导入默认追加。完全相同的上课安排默认不重复添加；同一时间但信息不同的条目交给用户核对。首版不提供截图直接覆盖整份课表。

### 5.4 课表首页

页面顶部展示学期名称、今天日期和当前教学周。

下一节课程卡片：

- 有正在进行的课程时，优先显示“正在上课”、课程名、教室和结束时间。
- 没有正在进行的课程时，显示今天最近一节未开始的课程及开始时间。
- 今天已经无课时显示“今日课程已结束”；全天无课时显示“今天没有课程”。
- 存在未来课程时，可附带展示最近一次上课日期和课程。
- 同时存在多门课程时显示冲突提示，并允许查看全部课程。

电脑端默认展示七天周课表；手机端默认展示今日课程列表，同时提供“周课表”切换。周视图完整显示周一至周日，窄屏允许横向滚动，固定节次列，避免把课程文字压缩到无法阅读。

周课表要求：

- 顶部支持上一周、下一周、选择教学周、返回本周。
- 每列同时显示星期和实际日期。
- 课程卡片显示名称、教室和节次；点击查看完整详情。
- 同一课程使用稳定颜色，不能仅靠颜色区分状态。
- 当前日期和当前节次清晰标记；课程冲突不得通过覆盖卡片隐藏。
- 某周无课时显示空状态和添加入口。
- 学期开始前或结束后显示“学期尚未开始”或“学期已结束”，仍可浏览该学期；默认分别展示第一周或最后一周。

### 5.5 课程详情与编辑

详情展示课程名称、教师，以及所有上课安排。每组安排独立包含星期、节次、周次和教室。

例如：“高等数学”可以有两组安排：周一第 1–2 节在 A101，周四第 3–4 节在 B203，分别设置上课周次。

操作入口：

- “编辑课程”：修改课程信息及重复上课安排。
- “调整本次”：针对用户选中的具体日期停课、换教室或改期。
- “删除课程”：二次确认后，删除该课程全部安排及相关单次变更。

新增课程至少包含一组有效安排；一次性补课可以关联已有课程，也可以创建独立课程记录。

### 5.6 设置与备份

- 查看和修改学期信息及作息时间。
- 展示“课表保存在此浏览器，清理网站数据可能导致丢失”的简短说明。
- 导出结构化备份文件，包含学期、课程、上课安排和单次变更。
- 恢复备份前校验格式与版本，展示学期名称、课程数量和变更数量。
- 首版恢复采用整份替换，明确说明将替换当前数据，并提供先导出当前备份的入口；用户确认后再执行。
- 格式不支持、数据不完整或恢复失败时，不修改已有课表。

## 6. 核心业务规则

### 6.1 教学周与时间

- 一周从周一开始；用户设置的第一教学周周一为第 1 周起点。
- 当前教学周 = 当地日历日期与起点相差的完整周数 + 1。按日历日计算，避免直接用毫秒差处理夏令时问题。
- 首版统一使用 Asia/Shanghai 时区，页面时间和课程判断保持一致。
- 只显示当前查看周实际开课的安排。
- 节假日不自动推断停课，也不自动把某天映射成另一星期的课程；用户通过单次变更处理。
- 非连续节次拆为多组安排，不把中间空闲节次合并为一堂课。
- 开始时间包含在“正在上课”的区间内，结束时间不包含；按配置的节次时间判断。
- 页面保持打开或重新回到前台时，更新当前日期、教学周和下一节课程。

### 6.2 周次表达

支持全学期、连续区间、区间内单周或双周，以及自定义周次集合。例如：

- 第 1–16 周。
- 第 1–16 周中的单周，即第 1、3、5……15 周。
- 第 2–12 周中的双周，即第 2、4、6……12 周。
- 第 1–4、6、8–12 周。

单双周以学期教学周编号为准。保存后统一得到实际周次集合，去重并排序；超出学期总周数的输入必须修正。

### 6.3 单次调课、停课与补课

- “调整本次”必须明确展示原日期和原节次。
- 停课仅取消该次课程；周视图不再将其作为正常课程显示，当日列表保留“已停课”记录供查看和恢复。
- 修改教室仅影响该次课程。
- 改期后原时段不再上课，目标日期展示课程并标注“由 X 月 X 日调入”；支持跨教学周，但目标日期必须在当前学期内。
- 一次性补课只在指定日期生效。
- 单次变更优先于原重复安排；同一原课程实例只允许一份当前有效的变更，重复编辑更新已有变更。
- 取消变更后恢复原始安排；删除一次性补课不影响其他课程。
- 变更后的课程也参与时间冲突检查和下一节课程计算。

### 6.4 修改基础配置的影响

- 修改学期起点会整体移动重复课程的实际日期；已记录的单次变更保持其具体日历日期，保存前提示影响。
- 如果新的学期范围使单次变更超出范围，或使其原始课程实例无法匹配，要求用户处理这些变更后再保存。
- 缩短总周数时，列出超出范围的课程周次；用户确认裁剪后才能保存，不静默丢弃。
- 修改节次时间后，相关课程显示与下一节判断使用新时间。
- 减少节次数量时，如果课程仍引用被移除节次，必须先修改相关课程。
- 编辑重复安排导致已有单次变更无法匹配时，列出受影响记录，用户选择取消此次编辑或清除这些变更后保存。

### 6.5 冲突与重复

- 两条实际课程在同一天且时间区间重叠时视为冲突；首尾相接不算冲突。
- 单周课与双周课仅占用相同星期、节次但没有共同周次时不冲突。
- 同一课程的星期、节次、周次、教室完全相同，视为重复安排。
- 不同教室或教师的信息差异不能自动合并；同名课程仅作为可能关联的提示。
- 冲突是提示，不是强制禁止保存；页面必须让用户看见冲突双方。

## 7. 数据对象

以下用于统一产品和开发理解，不限定数据库或前端框架。

| 对象 | 核心字段 |
|---|---|
| 学期 | 标识、名称、第 1 周周一、总周数、时区 |
| 节次时间 | 节次编号、开始时间、结束时间 |
| 课程 | 标识、名称、教师（可空）、展示颜色 |
| 重复安排 | 标识、课程标识、星期、起止节次、实际周次集合、教室（可空） |
| 单次变更 | 标识、重复安排标识、原始日期、类型、目标日期及节次（如适用）、教室覆盖值 |
| 一次性课程 | 标识、课程标识、日期、起止节次、教室 |
| 导入草稿 | 识别条目、字段问题、核对状态；原图只用于本次核对，不进入课表备份 |
| 备份 | 格式版本、导出时间、学期及全部课程数据 |

教师首版按课程填写；如一门同名课存在不同教师，可建立独立课程。教室按每组安排填写。

## 8. 异常、隐私与可靠性

### 8.1 关键异常反馈

| 异常 | 处理方式 |
|---|---|
| 图片过大或格式不支持 | 上传前说明限制，允许重新选择 |
| 识别请求失败、断网或超时 | 明确失败状态，允许重试或手动添加，不改变已有课表 |
| 返回的识别数据不完整 | 能展示的条目进入核对页，缺失项标记；不可解析时提示重新上传 |
| 识别结果没有课程 | 提示换一张清晰完整的截图，并提供手动添加入口 |
| 本地存储不可用或保存失败 | 明确提示未保存，保留当前页面数据，提供备份导出入口 |
| 关闭未保存的编辑或核对页 | 页面内离开操作二次确认；浏览器关闭提示尽力提供，不承诺草稿自动恢复 |
| 备份恢复失败 | 展示原因，保留原数据 |

### 8.2 数据与隐私

- 上传前说明图片会被发送给识别服务处理，建议裁掉姓名、学号等信息。
- 应用服务端默认不持久保存原图，不在日志中记录原图或完整课表内容。
- 选择识别供应商时确认其数据保留政策，并在上线前向用户说明；未确认前不能声称第三方不保留数据。
- 不公开课表，不提供默认分享链接。
- 不把课程名称、教室、原图等内容放入使用统计；首版试用统计以自愿参与为前提。
- 识别服务密钥保存在服务端，并设置上传大小、请求频率和费用上限。

### 8.3 浏览器与性能

- 验证当前主流版本的 Android Chrome、iOS Safari，以及桌面 Chrome、Edge、Safari。
- 覆盖 360px 宽手机到桌面屏幕；不承诺首版覆盖所有内嵌浏览器。
- 本地已有课表且页面已加载时，周次切换目标为 200ms 内完成。
- 核心文字清晰可读，操作支持键盘访问，错误和状态不只依赖颜色表达。
- 首版不承诺离线启动；页面已加载后的本地查看和编辑不应依赖识别服务可用性。

## 9. 验收标准

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A01 | 首次手动建表 | 不上传截图也能完成学期设置、创建课程并在对应周看到课程 |
| A02 | 标准截图导入 | 能进入核对页，修改后保存；保存前不污染已有课表 |
| A03 | 周次缺失 | 明确要求确认，不默认扩展到全学期 |
| A04 | 单双周 | 第 3 周只显示符合第 3 周规则的安排，第 4 周同理 |
| A05 | 多组安排 | 同一课程在不同日期、教室和周次的安排分别正确显示 |
| A06 | 日期边界 | 周日到周一、学期开始前后、学期结束后状态正确 |
| A07 | 下一节课程 | 课前、开始时、结束时和今日无课时均显示正确；冲突时可查看全部课程 |
| A08 | 单次停课 | 仅影响选中日期，后续周不受影响；可恢复 |
| A09 | 跨周调课 | 原时间不再作为有效课程，目标时间出现一次，下一节卡片同步更新 |
| A10 | 冲突检查 | 同一天实际时间重叠会提示；不同周次或首尾相接不会误报 |
| A11 | 重复导入 | 完全相同的安排默认跳过，有差异的信息进入核对 |
| A12 | 刷新与重开 | 同一浏览器中已保存的课表仍可读取 |
| A13 | 备份恢复 | 可恢复周次和单次变更；无效文件不会覆盖旧课表 |
| A14 | 识别失败 | 明确结束等待，提供重试和手动入口，原课表不变 |
| A15 | 移动端查看 | 360px 宽屏幕下今日列表可正常使用，周视图可查看全部星期 |
| A16 | 修改基础配置 | 超出范围的安排及失去关联的单次变更可见，未经处理不会静默丢失 |
| A17 | 存储失败 | 不显示保存成功，用户可导出当前数据 |

## 10. 开发拆分建议

按可验收的阶段推进，开发工期在原型和技术方案确定后估算。

1. 课表基础：学期设置、数据结构、手动录入、本地保存、今日与周视图。
2. 规则完整性：单双周、自定义周次、多组安排、冲突、单次调课和停课。
3. 智能导入：上传、识别接口、草稿核对、重复导入处理、错误反馈。
4. 试用准备：备份恢复、移动端适配、验收案例、真实截图验证和隐私说明。

首轮试用的交付标准是完整走通建表与日常查课，并通过以上关键规则验收。后续优先级根据实际观察决定：录入困难就优化识别和核对，日常查看困难就优化首页；同步和提醒在需求得到验证后进入下一版本。
